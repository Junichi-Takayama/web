## 4. 運用・契約上の注意点（トラブル防止・責任分界点）

### 4.1 DNS・メール設定事故の徹底防止（最重要）
1. **既存メールレコードの完全移送**
   * Cloudflare DNSへ移行する際、既存メールサーバー（さくらメール等）の `MX` / `SPF` / `DKIM` / `DMARC` レコードを漏れなく転記・設定すること。
2. **端末サポートの範囲明確化**
   * 「クライアントのPCやスマホ端末（Outlook, iPhone等）へのメールアカウント設定作業・トラブル対応はサポート対象外（別料金）」と契約書および案内文に明記する。

### 4.2 月2回更新代行の「SLA（作業スコープ）」

* **更新代行の定義**: クライアントから提供された原稿テキスト・画像素材の入稿・差し替え作業。
* **対応範囲**:
  * お知らせ・ブログ記事の投稿（1回あたり1記事）
  * 施工事例・写真ギャラリーの追加（1回あたり写真10枚以内）
  * 既存テキスト・写真の軽微な修正
* **対象外（追加見積）**:
  * ページの新規作成（レイアウト構築を伴うもの）
  * キャッチコピー・文章の新規執筆・取材
  * 特殊な画像加工・ロゴデザイン制作
  * 繰越不可（当月未利用の更新回数を翌月に繰越することは不可）
* **納期SLA**: 素材受領後 **2〜3営業日以内** に本番反映。
* **microCMS導入時の運用**: クライアントが自社でmicroCMSから更新を行う場合、月2回更新代行枠は「microCMS操作サポート」「入稿不具合の調整」「画像レイアウト調整」等に充当・活用可能。


### 4.3 Formrun（問い合わせフォーム）の仕様範囲
* **標準仕様**: 無料プラン（通知先メールアドレス1件のみ）。
* **拡張オプション**: 複数人への同時通知、自動返信メールの高度なカスタマイズ、サンクスページのリダイレクト等はクライアントによる有料プラン契約が必要。

### 4.4 更新代行の自動化ワークフロー（ワンクリック承認＆自動マージ公開仕様）

ディレクター（高山様）の手離れを極限まで高め、更新反映〜本番公開の工数を最小化するための自動化ワークフローを標準仕様とする。

```
[エンドクライアント（工務店等）]
    │ ・日常発信はInstagramや代表noteへ直接投稿（サイト側で埋め込み・導線連携）
    │ ・年数回の施工事例や見学会は、代理店の定例訪問・MTG時に口頭/写真提供
    ▼
[販売代理店（コンサルタント）]
    │ 定例ヒアリングのついでに素材（写真・テキスト）を回収・一次整理
    │ 高山様へ更新依頼として投下（顧客折衝・一次窓口を完結）
    ▼
[ディレクター / Cline (AI)]
    │ 依頼内容を読み取り、作業ブランチ作成 → コード修正・構築 → commit & push
    ▼
[Cloudflare Pages (CI/CD)]
    │ ブランチ専用のプレビューURLを自動発行（1〜2分）
    ▼
[Cline (AI) ➔ 高山様]
    │ プレビューURLと修正差分を高山様へチャット報告
    ▼
[高山様]
    │ プレビュー確認後、「承認、送信して」と指示（★高山様の稼働はここで完了）
    ▼
[Cline (AI)]
    │ クライアント概要から宛先を取得し、Mac「メール」経由でクライアントへ確認依頼メールを自動送信
    │ ※高山様のGmail（BCC）にも同時送信され、ブラウザGmail上で送信状況・受信トレイの両方で確認可能
    ▼
[クライアント]
    │ メール内の「この内容で本番サイトに公開する」リンクをクリック
    │ ➔ 確認画面で［本番公開を実行する］ボタンを押下
    ▼
[Cloudflare Worker / GitHub API]
    │ 承認トリガーを受信し、該当GitHub PRを自動マージ
    ▼
[Cloudflare Pages]
    │ 本番環境へ自動ビルド & 即時公開完了
    ▼
[自動通知]
    │ 高山様およびクライアントへ「本番公開完了メール」が自動配信
```

* **安全ガード（誤送信・誤爆防止）**:
  * 高山様がプレビューを確認して承認指示を出すまで、クライアントへのメールは送信されない。
  * メール内の承認リンク押下後、1回「実行確認ボタン」を挟むことで、セキュリティソフトの自動巡回や誤タップによる意図しない本番公開を防止する。
* **高山様のメリット**:
  * クライアントからの返信待ちやメール確認、手動でのマージ作業が不要となり、クライアントが承認した瞬間に自動で本番公開まで完了する。



## 5. Astro × AI（Cline）開発・技術標準仕様

### 5.1 コーディング・開発基本ルール
Astro公式ガイドライン（Build with AI）に準拠：
1. **初期化・パッケージ追加**:
   * 追加インテグレーションは `npx astro add tailwind` などの公式CLIコマンドを使用（`package.json` を手動編集しない）。
2. **コンテンツ管理 (`astro:content`)**:
   * ブログ・お知らせ・施工事例などの動的コンテンツは Content Collections（`src/content/`）で型安全に管理する。
3. **画像処理 (`astro:assets`)**:
   * 画像出力は原則 `<Image />` コンポーネントを使用し、自動WebP変換・レスポンシブ最適化を行う。
4. **CSS・スタイル**:
   * Tailwind CSS または スコープ付きCSS (`<style>`) を使用する。BEMや長大なグローバルCSSの手動作成は禁止。

### 5.2 JSアニメーション仕様（`src/scripts/animate.js`）
* **方式**: ピュアJS（`IntersectionObserver` API）による軽量演出。
* **属性指定ルール**:
  * `data-animate="fade-up"` （下からフェードイン）
  * `data-animate="slide-left"` （左からスライド）
  * `data-animate="slide-right"` （右からスライド）
  * `data-animate="scale-up"` （拡大表示）
  * `data-delay="100"` ~ `300` （Stagger順次遅延表示）

### 5.3 SEO・OGP・アクセシビリティ標準
* **SEO基本仕様**: `<head>` 内に meta title, description, canonical, OGP (og:image, og:title, og:description) を標準設置。
* **自動生成**: `@astrojs/sitemap` によりビルド時に `sitemap-index.xml` を自動生成。
* **HTML構造**: セマンティックなHTMLタグ（`<header>`, `<main>`, `<nav>`, `<footer>`, `<article>`, `<section>`）を徹底。

### 5.4 microCMS連携仕様（CMS自社更新要望時）
* **標準採用**: クライアント側で自社更新（お知らせ・施工事例・ブログ等）を行いたい要望がある場合は、日本製の国産ヘッドレスCMS **microCMS** を標準採用する。
* **データ取得**: `microcms-js-sdk` を用い、Astroのビルド時に API 経由で型安全にコンテンツを取得して静的HTML（SSG）を生成する。
* **自動プレビュー・WebHook連携**: microCMSでコンテンツを「公開/更新」した際、Cloudflare Pages の Deploy Hook （Webhook）を自動実行し、2〜3分程度で本番サイトへ自動再ビルド・即時反映される構成を初期構築する。
* **アカウント・料金プラン**: 原則クライアント契約（無料プラン〜、必要に応じて有料プラン案内）とし、APIスキーマ構築および初期入稿画面の基本セットアップは弊社で対応する。
* **インフラ原価とターゲット規模**: 主要ターゲット（月間UU 2,000未満の地方零細企業）のアクセス規模であれば、microCMS（月間転送量20GBまで無料）および Cloudflare Pages の無料枠内で100%運用が完結し、インフラ原価0円・高粗利構造を維持可能。


### 5.5 Astroカタログ蓄積 × Claude Code × Figma 双方向プロトタイピング仕様
一人（個人事業）でも圧倒的な初速と手離れの良さを維持するため、制作資産をGitカタログとして蓄積し、Claude CodeとFigmaを連携させて高速制作を行う。

1. **構成・WF先行フロー（通常案件）**:
   - Gitリポジトリ内のカタログパーツ（`/catalog/` 配下のHeader, Hero, About, Works, CTA, Footer等）から必要なパーツIDを選定。
   - Claude CodeにIDリストを渡し、Astroで動くモックアップを即時生成。
   - Chrome拡張（`html.to.design` 等）でブラウザモックをFigmaへ取り込み、色・フォント・画像を詰めてデザイン確定。確定内容をスタイルへ逆輸入。
   - ★**効果**: ワイヤーフレーム作成作業を全廃し、初回から「実機で動くモック」を提示可能。
2. **デザイン先行フロー（企画・紙媒体先行案件）**:
   - チラシ・パンフレット先行や、Auto Layoutが効いていない絶対配置のFigmaデザインが提供された場合でも、Figma PAT / MCP経由でClaude Codeに読み込ませる。
   - Claude Codeが視覚的配置・階層構造・テキストを解析し、`/catalog/` から構造が近いAstroコンポーネントを自動選定して流し込む。
   - ★**効果**: デザイナーへの差し戻しや手動でのAuto Layout修正をゼロにし、自動で「綺麗なFlex/Grid構造・レスポンシブ対応コード」へ清書。
3. **カタログへの制作資産還元ルール**:
   - 各案件で新しく開発した汎用セクションは、納品時にダミーデータ化（抽象化）してGitカタログへ追加登録し、次回案件の制作資産としてストックする。

## 7. 解約時・サービス移行規定（ハンドオーバー仕様）

1. **引き渡しデータ**
   * ビルド済み静的Webデータ一式（HTML/CSS/JS/画像）
   * 希望に応じて GitHub ソースコードリポジトリのアクセス権渡しかZip納品
2. **ドメイン**
   * AuthKey（ドメイン移管コード）を発行し、クライアントが指定する管理事業者へ譲渡。
3. **責任境界**
   * 移行先サーバーへのアップロード作業、移転先でのDNSレコード設定、メール再設定等はクライアントまたは移行先業者の対応範囲とする（弊社で代行する場合はスポット作業として別途見積）。
