# 新規Web制作・保守運用サービス構想

## 1. 企画の概要

地方の中小・零細企業、特に小規模工務店などを対象とした、Webサイト制作および保守・更新代行サービス。

ただし、一般的なWeb制作会社のように自社で新規営業を行うモデルではない。

経営コンサルタントやブランディングコンサルタント等を**販売代理店・顧客フロント**として活用し、自分自身はWeb制作・デザイン・実装・技術対応に集中する。

### 目的

- 新規営業を自分で行わない
- Web制作を標準化する
- 制作案件を継続的な月額契約につなげる
- 低工数のストック収益を積み上げる
- 個人事業として一人でも運営可能なモデルを作る
- 実際に需要が増えた場合のみ、人材採用や法人化等の事業化を検討する

現時点では30社などの規模を前提にした事業計画ではない。

まずは実際に1社、数社で、

1. 売れるか
2. 問題なく制作できるか
3. 想定した運用工数で回るか
4. 同じ販売代理店から継続して案件が来るか

を検証する段階。

# 2. ビジネスモデル

## 基本構造

単なる案件紹介制度ではなく、**販売代理店・OEMに近い構造**。

```text
自分
│
├─ Web制作サービスの提供
├─ Web戦略・情報設計
├─ デザイン
├─ 実装
├─ インフラ・技術対応
├─ 保守管理
├─ 更新作業
│
↓
│ Web制作・技術バックエンド
↓
│
販売代理店／コンサルタント
│
├─ 顧客開拓
├─ 営業
├─ 提案
├─ 顧客窓口
├─ ブランディング支援
├─ 素材回収
└─ 入稿データ整形
│
↓
エンドクライアント
```

自分は原則としてエンドクライアントに直接請求しない。

自分は代理店に対して、

- 制作費
- 保守・更新代行費
- 追加要件の費用

など、自分が受け取る金額・卸価格を提示する。

代理店側はエンドクライアントへの販売価格を自由に設定できる。

### 月額保守・収益分配スキーム（確定モデル）

自分は**卸価格「月額5,000円〜10,000円」**で代理店に提供する。代理店側の提案状況に応じて以下の2パターンで展開する：

#### パターンA：代理店の「コンサル契約あり」の場合（主力・推奨）
```text
【エンドへの提示】
  コンサルティング費用：月額 〇〇万円
  （※「Webサイトの保守・月2回更新代行までコミコミでお任せ」という見せ方）
       │
       ▼
【裏側の配分】
  ・代理店：コンサル料を満額受領 ＋「サイト管理も丸投げできる」という強力な解約防止フックを獲得
  ・自分：毎月 5,000円〜10,000円 を代理店から安定受領（純粋な不労・低工数ストック）
```

#### パターンB：コンサルなし・「保守単体」の場合
```text
【エンドへの提示】
  Webサイト保守・運用代行：月額 15,000円（税別）
       │
       ▼
【裏側の配分（折半モデル）】
  ・代理店：月額 7,500円（何もしなくても毎月入るストック手数料）
  ・自分：月額 7,500円（卸価格として受領）
  （※または自分10,000円 / 代理店5,000円など案件難易度に応じて調整）
```

#### このスキームが機能する理由
1. **代理店側の強烈なインセンティブ**:
   - パターンAなら「自社コンサルの成約率アップ・解約防止」になり、パターンBなら「ノーリスクで毎月のチャリンチャリン（ストック手数料）」が手に入る。
2. **窓口・一次対応の納得感**:
   - 代理店側に毎月利益が落ちるため、泥臭い素材回収や一次連絡窓口を嫌がらずに担当してくれる。
3. **自分の作業量と価格の完全一致**:
   - 年間10棟工務店の更新頻度（年数回）であれば、月5,000〜10,000円でGit/Markdown反映作業を行うのは時間単価・粗利率ともに極めて高い。

4. **コンサル側の社内オペレーションが成立する理由（10分で5,000円の利益）**:
   - コンサルタント本人すら手を動かす必要がない。現場で素材を受け取ったら、自社の事務員やアルバイトに「これ高山さんに送れるように整理しといて」と渡すだけ。
   - 事務・バイトの作業時間はわずか10分程度。それだけで毎月5,000円〜7,500円の粗利が残る。
5. **コンサル契約の解約防止（リレーション維持）の口実になる**:
   - コンサルタントにとって最大の解約原因は「顧客との接触頻度の低下」。
   - 「今月の施工写真や現場情報ありますか？」という素材回収連絡が、**顧客と定期的に接触し続けるための自然で強力な口実**になるため、コンサル側にとっても非常にメリットが大きい。
6. **更新依頼ポータルの真の役割（代理店・事務スタッフ専用の入稿UI）**:
   - **エンド顧客（工務店）には絶対に見せない・触らせない**:
     - 顧客にフォーム入力を求めると「それなら管理画面があった方が早い」と本末転倒になる。顧客体験はあくまで「LINEで写真とテキストをポイ投げ」「コンサルに口頭で伝えるだけ」の完全丸投げを徹底する。
   - **コンサルの事務・バイト向けの「データ構造化＆画像圧縮ツール」として渡す**:
     - 工務店から届いたバラバラの素材を、コンサルの事務やバイトがポータル（`/request`）の項目に沿って入力するだけで、必要なヒアリング項目（延床面積、構造、写真キャプション等）が漏れなく揃う。
     - スマホ写真の自動WebP軽量化により、容量エラーを起こさず1クリックで「Markdown＋WebP画像のZIP」が生成される。
     - バイトは出来上がったZIPを高山様へ送るだけ。高山様への手戻り・確認連絡がゼロになり、双方が最もストレスなく10分で完結する。



---
7. **ツールの二面性（外部ポータル 兼 自分用制作・運用コックピット）**:
   - **サイトごとの差異への柔軟な対応**:
     - 案件ごとにスキーマ（入力項目）の微差があるため、無理に全クライアント・代理店へ固定フォームを配る必要はない。
   - **自分用の「爆速オーサリング・画像変換ユーティリティ」としての実用性**:
     - コンサルから生写真（10MBの重いJPGやiPhoneのHEIC）と雑なテキストが届いた場合でも、**高山様自身がこのポータルを開いて写真を放り込むだけで、PhotoshopやSquooshを使わずに一瞬で「WebP軽量化 ＋ リネーム ＋ Markdown下書き」が完成**する。
     - 最悪「コンサルから生データ受領 ➔ 自分がポータルで数クリック ➔ ローカルに最適化済みWebPとMDを即時生成」という自分専用コックピットとして使うだけでも、更新作業の工数が劇的に削減される。


# 3. 販売代理店モデルのメリット

代理店にとっては、単にWeb制作会社を紹介するだけではない。

自社サービスにWeb制作・保守・更新代行を組み込める。

例えば、

## 従来

月額50,000円

- 経営コンサルティング
- ブランディング支援

## 拡張後

月額50,000円〜

- 経営コンサルティング
- ブランディング支援
- Webサイト保守
- 更新代行

という商品設計が可能。

顧客からすると、

> コンサルを頼んでいるだけなのに、ホームページの面倒まで見てもらえる

という付加価値になる。

代理店は自社でWeb制作者やエンジニアを抱える必要がない。

自分は営業をしなくても案件を獲得できる。

# 4. 想定ターゲット

主なターゲットは地方の中小・零細企業。

特に、

- 年間10棟前後の小規模工務店
- Web専任担当者がいない企業
- WordPressサイトを放置している企業
- サイト更新を自社で行う余裕がない企業

などを想定。

## 典型的な課題

- WordPressの更新方法がわからない
- 日常の発信は「Instagram」と「代表note」が中心であり、Webサイト側の管理画面を触る習慣がない
- 施工事例は年間3〜10件程度、見学会イベントも月1回程度のため、高機能なCMSを導入しても持て余す
- 高機能CMS（WordPress等）の導入・保守・操作説明コストが無駄な負担になっている

### なぜ「CMS不要・更新代行・SNS埋め込み」が最適解なのか？

年間10棟以下の工務店における「発信の実態」から逆算すると、以下の構成が顧客・代理店・自分の三者にとって最も合理的となる：

1. **鮮度の維持は「Instagram埋め込み」と「note連携」で完結**:
   - 日常の現場風景や施主とのやり取りはInstagram、家づくりへの想いやこだわりは代表noteに投稿される。
   - サイト上にこれらを埋め込み・導線設計することで、サイト自体にCMSを持たなくても常に最新情報が動く状態を作れる。
2. **CMS導入・カスタマイズ・操作サポートのコストを完全カット**:
   - CMS（WordPressやmicroCMS）を入れると、初期API構築・GUI設計・操作説明・「ログインできない」「順番を変えたい」等のサポート負債が発生し、初期費用も月額も跳ね上がる。
   - CMSを排除することで初期費用を極限まで抑え、低予算でも導入しやすい価格設定を実現できる。
3. **コンサルタントの「月次訪問・定期MTG」のついでに回収する美しいフロー**:
   - 年に数件の施工事例やイベント情報は、コンサルタント（代理店）が定例ミーティングの際に写真と概要をヒアリングして回収。
   - 代理店から自分へ素材が渡され、自分がGit/Markdownでパッと整形・反映する。
   - 工務店からすれば「コンサルに話しただけでサイトにも反映される」という最高の手離れ体験となる。

※なお、「どうしても自社で即座にニュースやブログを更新したい」「更新頻度が週数回と非常に高い」という企業にのみ、**上位オプション（別途初期構築費用＋月額追加）としてmicroCMS導入を提案**する境界線を設ける。

- プラグイン更新やセキュリティ対応が不安
- 社内にWeb担当者がいない
- 本業が忙しくサイト更新まで手が回らない
- 施工事例は掲載したい
- ブログやお知らせも更新したい
- しかし毎回制作会社に依頼するのも面倒
- CMSを覚えたいわけではない

つまり、

> 自社でホームページを管理するほどの人員やリソースはないが、サイトを放置するわけにもいかない企業

が主なターゲット。

# 5. Web制作サービスの考え方

「60万円固定のテンプレートサイト」という商品ではない。

基本的な考え方は、

> 一般的なWordPress制作で100万円程度になる規模・品質のサイトを、標準化された制作方式により60万円程度から提供できる仕組み

を作ること。

案件によって価格は変動する。

## デザイン

デザインは基本的に案件ごとのオリジナル。

ただし、完全なフルスクラッチではない。

以下はあらかじめコンポーネント化・標準化する。

- UIコンポーネント
- セクション
- レイアウト
- デザインシステム
- コーディング構造
- ページ構造
- 更新用コンテンツ構造

それらを組み合わせ・アレンジすることで、オリジナルデザインを維持しながら制作効率を高める。

つまり、

> オリジナルデザイン × 標準化された制作

というモデル。


---

# 6. 制作工数と利益基準

制作費については、単純なページ数単価ではなく案件規模・必要工数で判断する。

個人事業としての目標時給は約5,000円。

例えば、

```text
制作費：600,000円
制作工数：100時間

＝ 時給6,000円
```

100時間程度であれば現時点では許容範囲。

重要なのは極端な効率化ではなく、

- 標準化によって適正な利益率を維持すること
- 想定を大幅に超える工数の案件を防ぐこと

である。

制作期間のイメージは1案件約3ヶ月程度。

ただし常に1案件だけを進めるのではなく、3サイト程度を並行して進行できる想定。

# 7. 技術スタック

基本構成：

- Astro
- Tailwind CSS
- Cloudflare Pages
- Cloudflare DNS
- 必要に応じてmicroCMS
- Formrun等の外部フォームサービス
- Git等によるバージョン管理
- ClineおよびAIを活用した制作・管理

## 技術選定の目的

技術自体を売ることが目的ではない。

以下を実現するための裏側の仕組み。

- 高速なWebサイト
- 低コストなインフラ
- WordPressのようなプラグイン管理の削減
- セキュリティ上の攻撃対象の縮小
- 制作工程の標準化
- AI活用による制作効率化
- 保守工数の最小化

Astroを採用する理由は、

> Astroだから売れる

ではなく、

> 低コストかつ低保守でWebサイトを運用できるサービスモデルを成立させやすい

ため。

# 8. microCMSによる拡張

基本モデルは「更新代行」。

つまり顧客自身にCMS操作を要求しない。

しかし、

- 自社でブログを更新したい
- 頻繁に施工事例を追加したい
- 本格的な管理画面が必要

などの場合は、microCMS等のヘッドレスCMSを導入する。

構造：

```text
顧客
↓
microCMS管理画面
↓
コンテンツ管理
↓
Astro
↓
静的サイトとして公開
```

これにより、

- CMSによる内製更新
- フロントエンドの高速性
- 静的サイト中心の構成
- WordPress本体やプラグイン管理からの解放

を両立する。

---

# 9. 保守・更新代行サービス

品目名称は、

> 保守管理・更新代行費

ただし実態として、静的サイト中心のためインフラ保守工数は比較的小さい。

そのため実質的なサービスの中心は、

> 標準化された更新作業の月額サブスクリプション

である。

## 基本イメージ

- 月2回までの更新
- 1記事追加＝1回
- 軽微な固定ページ修正＝0.5回換算など柔軟に対応
- 文章・画像差し替え程度は契約範囲内
- ページ追加は追加見積
- 新機能追加は追加見積
- 大規模な構成変更は追加見積

1回あたりの作業時間は約30分を想定。

---

# 10. 更新依頼の役割分担

このモデルで重要なのは、自分がエンド顧客から直接、

> 写真送ったのでいい感じに更新してください

のような雑な依頼を受けないこと。

基本フロー：

```text
エンドクライアント
↓
販売代理店／コンサルタント
↓
顧客対応
素材回収
文章整理
画像整理
入稿データ化
↓
自分
↓
Webサイトへ反映
↓
公開
```

代理店側には、サイトごとに定めた入稿テンプレートに沿って情報を整理してもらう。

例：

```text
タイトル：
公開日：
本文：

画像1：
画像2：
画像3：
画像4：
画像5：

備考：
```

理想は、

> そのままコンテンツとして流し込める状態

まで整形されたデータを自分が受け取ること。

自分は、

- データ確認
- 必要最小限の整形
- Webサイトへの反映
- デプロイ
- 公開確認

に集中する。

コピーライティング、写真選定、素材整理などまで自分が行う場合は、通常の更新代行範囲を超えるため追加費用とする。

```text
＝
Web制作・技術バックエンド
```

更新依頼については原則として代理店が窓口。

一方で、

- 新機能を追加したい
- サイト構造を変更したい
- 大規模なリニューアルをしたい

また、ブランディングや経営戦略に関わる部分については、コンサルタントにも積極的に参加してもらう。

役割分担：

```text
- 素材回収
- 顧客窓口

【自分】

- Web戦略
- 情報設計
- Webデザイン
- コーディング
- 実装
- 技術対応

- 保守
- 更新反映
```

# 12. 月額料金モデル

月額料金を必ずしもエンド顧客に一律10,000円で販売する必要はない。

重要なのは、

- 自分が受け取る金額
- 自分が担当する範囲
- 代理店が担当する範囲

である。

## パターンA：代理店が更新業務を大きく担当

```text
顧客への販売価格：10,000円

自分：5,000円
代理店：5,000円
```

代理店側が、

- 顧客対応
- 素材回収
- 文章整理
- 画像整理
- 入稿データ作成

までしっかり行う。

自分は反映作業を中心に担当。

## パターンB：Web単体サービス

```text
顧客への販売価格：15,000円程度
```

代理店を介さない直接案件などを想定。

自分が、

- 顧客対応
- 更新依頼対応
- 技術対応
- 更新作業

を行う。

## パターンC：コンサルサービスへの組み込み

代理店が、

> 月額50,000円のコンサルティングサービス

の中に、

- Webサイト保守
- 更新代行

を含める。

顧客へのWebサービス単体価格を明示しない。

代理店は自社サービスの付加価値として販売する。

自分と代理店の利益配分は、業務負担に応じて個別に設定する。

# 13. 販売代理店の考え方

特定の1社に依存しない。

複数のコンサルタント・コンサル会社・ブランディング支援会社等との協業を想定。

```text
自分
│
├─ 販売代理店A
├─ 販売代理店B
├─ 販売代理店C
└─ その他
```

代理店ごとに、

- 関係性
- 販売価格
- 利益配分
- 担当範囲
- 顧客対応範囲

が異なってもよい。

ただし、自分が提供するWeb制作・更新作業については一定の基準を持つ。

# 14. 管理方法

クライアント管理は、複雑なCRMやExcelを中心にするのではなく、

> Markdownファイル＋Cline＋AI

を活用する。

クライアントごとにMarkdownファイルを作成し、

- 契約内容
- 代理店
- 自分の月額収益
- 更新条件
- 更新回数
- 更新履歴
- 追加要件
- 保留事項

などを管理する。

例：

```text
/client-a/

client.md
contract.md
update-log.md
requirements.md
```

クライアント情報例：

```markdown
# Client A

## 基本情報

代理店：コンサルA
契約開始：2026-10

## 契約

自分への月額：5,000円
エンド顧客への販売価格：代理店管理

## 更新ルール

月間更新枠：2回

- 記事追加：1回
- 軽微な固定ページ修正：0.5回
- ページ追加：追加見積
- 新機能追加：追加見積

## 2026年9月

使用枠：1.5 / 2

### 更新履歴

- 09/03 お知らせ追加：1回
- 09/18 会社概要の画像差し替え：0.5回

## 追加要件

- 採用ページ追加：見積対応予定
```

ClineやAIに横断参照させることで、

- 今月の更新残数一覧
- 契約外依頼の判定
- 更新履歴の整理
- 追加見積対象の抽出

などを行う。

30社程度まで増えた場合も、人間が全案件を記憶して管理する前提ではない。

# 15. 将来的な規模

現時点で30社を目標として事業計画を作っているわけではない。

まずは、

```text
1社で売れるか
↓
実際に運用できるか
↓
代理店が2社目、3社目を販売できるか
↓
同じモデルが再現可能か
```

を検証する。

仮に結果として30社以上の需要が発生した場合、

- 人材採用
- 外注
- 法人化
- 業務のさらなる自動化
- 本格的な事業化

を検討する。

しかし現時点では皮算用をせず、実需が発生してから考える。

参考値として、

```text
30社 × 自分の平均取り分5,000円
＝ 月額150,000円

30社 × 自分の平均取り分10,000円
＝ 月額300,000円
```

ただし、これは将来の目標値ではなく、あくまでモデルが成立した場合の参考値。

# 16. サービスの本質

このサービスの本質は、

> Astroで安くWebサイトを作ること

ではない。

また、

> Web制作案件を大量に取ること

だけでもない。

本質は、

> 営業・顧客フロントを販売代理店に任せ、自分は標準化されたWeb制作と技術バックエンドに集中し、制作後は低工数の月額収益を積み上げること

である。

代理店側から見ると、

> 自社でWeb制作者やエンジニアを雇わず、Web制作・保守・更新代行を自社サービスとして販売できる

モデル。

自分から見ると、

> 営業をせず、制作・デザイン・実装に集中しながら、納品後のストック収益を作る

モデル。

---

# 17. 現時点での強み

- 自分で新規営業を行う必要がない
- コンサル側の商品価値を高められる
- 代理店側は販売価格を自由に設定できる
- 自分は必要利益を確保することに集中できる
- オリジナルデザインを維持しながら制作を標準化できる
- WordPressより保守工数を抑えやすい
- 納品後に月額ストックを積み上げられる
- 更新作業を構造化することで1回約30分を目指せる
- Markdown＋Cline＋AIで案件管理を効率化できる
- 特定の販売代理店1社に依存しない
- 小規模に開始し、実需に応じて拡大できる

# 19. 協業提案資料の位置づけ

作成予定の8ページ資料は、エンドクライアント向け営業資料ではない。

販売代理店候補となるコンサルタント向けの協業提案資料。

目的は、

> このWebサービスを自分たちの商品として販売・組み込みできる

と理解してもらうこと。

資料で伝えるべき内容は、

1. どのような顧客に販売できるか
2. 顧客のどの課題を解決できるか
3. WordPressやノーコード型サービスと何が違うか
4. なぜ低価格・低保守で成立するのか
5. 自分と代理店の役割分担
6. 保守・更新代行の仕組み
7. 工務店向けWebサイトの具体例
8. 代理店が得られるメリット

特にスライド8は単なる「協業メリット」ではなく、

> 販売代理店として、自社サービスにWeb制作・保守・更新代行を組み込める

ことを明確にするページとして設計する。
